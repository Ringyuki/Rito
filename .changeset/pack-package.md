New package for servers. `packPublication(epub, { encrypt })` splits an EPUB into the shards a reader opens it from — the skeleton and one shard per image, audio or video file, each `{ id, bytes, key, files }`, whose `{ id, bytes, key }` is what a reader's `loadShards` returns — without a Rust toolchain. `checkPublication(epub)` says whether the reader can read a book: unreadable with the error the reader fails on (the archive or package document does not open, a listed chapter or font cannot be read, a chapter links a stylesheet the package lacks), or readable with the files it shows degraded (a chapter whose XHTML does not parse shows no content; a listed stylesheet, font or image the archive lacks is left out). Both run the engine's own code as WASM, each call on a worker thread of its own, so the caller's event loop keeps serving and the memory is released when the call ends. The `rito-pack` command packs a book into a directory (`skeleton.rshd`, `shards/`, `manifest.json`, and `keys.json` with `--encrypt`) or checks one with `--check`. Image, audio and video shards are now deflated at a lower level: packing takes half the CPU time it did, for shards 0.6% larger.
