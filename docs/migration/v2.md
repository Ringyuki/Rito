# Migrating to 2.0

2.0 removes API that described how the engine used to work rather than
what it does. Almost every removal below is something the engine no
longer has rather than something that moved: a book is paginated whole
in one call, the engine measures its own text, and page content is
derived rather than projected. Where a name did only move, the new home
is given.

How much work this is depends on what you use. A reader that opens a
book and turns pages changes a handful of lines. A reader that draws
selections, annotations or its own hit targets changes more, because
those went through a page projection that is gone. A host that decodes
the display list and paints it itself changes most — that list is format
2, and the section below is the one to read first.

## `@ritojs/core`

### `Reader.pages` and the `Page` type are removed

`Reader.pages` was a fabricated array: every entry carried the layout's
page size as its `bounds` and an always-empty `content`. Nothing real
lived there.

```ts
reader.pages.length; // -> reader.pageCount
reader.pages[0]?.bounds; // -> reader.getLayoutGeometry() (pageWidth, pageHeight)
reader.pages[i].content; // no replacement: it was always []
```

Page content — text, hit targets, semantics — comes from
`reader.interactions` against the committed revision.

### `Spread` is the engine's navigation record

```ts
// before
interface Spread {
  index: number;
  left?: Page;
  right?: Page;
}
// after
interface Spread {
  index: number;
  pageIndexes: readonly number[];
  leftPageIndex: number;
  rightPageIndex?: number;
}
```

```ts
spread.left?.index; // -> spread.leftPageIndex
spread.right?.index; // -> spread.rightPageIndex
[spread.left, spread.right].filter(Boolean); // -> spread.pageIndexes
```

`left` was optional and `leftPageIndex` is not: a spread always has a left
page, so a host that guarded on `spread.left` can drop the guard.

`reader.spreads`, `totalSpreads`, `findSpread()` and `findPage()` keep
their signatures on the new shape.

### `Reader.pagination` is removed

A revision is created complete, so `complete` was always `true` and
`ensureSpread(i)` only compared `i` against `totalSpreads`.

```ts
if (!reader.pagination?.complete) …          // -> delete the branch
await reader.pagination?.ensureSpread(i)     // -> if (i < reader.totalSpreads)
```

`totalSpreads` is final from the first frame a host can ask for, so a
progress bar built on it no longer moves after open.

### `Reader.measurer` is removed

`TextMeasurer`, `TextMetrics`, `MeasurePaint` and `FontShorthand` go
with it. The browser implementation returned eight pixels per character;
all real measurement happens in the engine, and text geometry comes from
`reader.interactions`.

### Layout options that did nothing are removed

```ts
createReader(data, canvas, { lineBreaking: 'optimal', paginationPolicy: … })
reader.setLineBreaking('greedy')
```

The engine has one line breaker, and widow and orphan control comes from
the book's own CSS. `PaginationPolicy` goes with them, so
`LayoutConfig.paginationPolicy` and the `paginationPolicy` accepted by
`createLayoutConfig()` are removed too, as is
`LayoutConfig.textMeasurement` — shaping is always font-aware.

### `V1` suffixes are gone

Nothing in the repository ever had a second version, so the suffix
carried no information. Drop it:

```ts
openBrowserReaderV1                    // -> openBrowserReaderSession
createBrowserReaderV1CanvasPresenter   // -> createBrowserReaderSessionCanvasPresenter
BrowserReaderV1Session                 // -> BrowserReaderSession
BrowserReaderV1OpenOptions             // -> BrowserReaderSessionOpenOptions
RitoReaderErrorV1, BrowserReaderArtifactV1, …   // -> the same name without V1
```

The two places that still name a version are the wire magic tags, whose
trailing digit a decoder checks, and the numeric protocol version.

### The work budget is removed

`BrowserReaderWorkBudgetV1` is removed outright: the session never read
the budget it carried. It took a required field with it in two places, so
a call that compiled against 1.0.1 stops compiling until the field goes:

```ts
openBrowserReaderSession(publication, { layout, initialLocator, work }); // drop `work`
session.requestArtifact({ locator, layout, textProfile, work }); // drop `work`
session.seek(locator, { layout, work }); // drop `work`
session.requestAdjacent(id, direction, work); // drop the third argument
```

### The canvas presenter carries its own ratio

`prepare()` took a `pixelRatio` and paint took another; the ratio is now
decided once, when the artifact is prepared, and reported back.

```ts
presenter.prepare(artifact, { pixelRatio }); // -> presenter.prepare(artifact)
paintOptions.pixelRatio; // -> prepared.ratio
```

`BrowserReaderCanvasPrepareOptions` is removed — `prepare()` takes only
the artifact — and `BrowserReaderCanvasPaintOptions` keeps `clear`,
`backgroundColor` and `foregroundColor` but loses `pixelRatio`.
`BrowserReaderPreparedCanvasArtifact` gains `ratio`, and
`BrowserReaderLayout` accepts an optional `renderRatio`.

### Two artifact fields are gone

```ts
artifact.terminalExtent; // no replacement: read artifact.navigation
```

`BrowserReaderAdjacentAvailability` loses `'pending'` and `'blocked'`; it
is now `'available' | 'chapter-boundary' | 'terminal'`. An artifact is
created complete, so neither of the dropped states could occur. A host
that switches on it can delete those branches.

### The display list is format 2

This is the largest change in the release for a host that decodes paint
output itself. `artifact.displayList.formatVersion` is `2`, not `1`, and
the command vocabulary behind it is replaced wholesale: a flat
`RitoReaderDisplayList` of tagged commands — `paint-block`,
`paint-text`, `paint-image`, `transform`, with `RitoReaderBlockPaint`,
`RitoReaderBackgroundPaint`, `RitoReaderBorderEdgePaint`,
`RitoReaderCornerRadii`, `RitoReaderLength`, `RitoReaderBorderStyle`,
`RitoReaderRunBorder` and `RitoReaderRunBorderEdge` — becomes a
`RitoReaderPrimitiveList` of `RitoReaderPrimitive`. Every one of those
command types is removed.

`RitoReaderRunPaint` shrinks to the glyph run itself. The box geometry
and box decoration it used to carry — `top`, `bottom`, `left`, `right`,
`y`, `backgroundColor`, `backgroundRadius`, `border`, `padding`,
`decoration`, `letterSpacingPx`, `wordSpacingPx` — are gone: inline
boxes and decoration lines are lowered by the engine and arrive as their
own primitives, so a pen no longer reconstructs them from a text run.

A host that only hands the display list to the bundled presenter needs no
change. A host with its own blitter is rewritten against the primitive
list, and must check `formatVersion` before decoding.

## `@ritojs/kit`

### The page/hit-map interaction path is removed

`buildHitMap` and `resolveAnnotations` leave the entry point together
with the path they served: the synchronous selection engine, the link
and hit maps, the page-walking accessibility source and the page-text
search index. They read `Page.content`, which was always empty, so in
production they resolved nothing. Selection, clicks, search highlights,
annotations and the accessibility mirror all read `reader.interactions`,
and always did.

So the features are unaffected: code that reaches selection, annotations
or search through the controller or the React hooks keeps working and
only renames the fields below. Only code that imported `buildHitMap` or
`resolveAnnotations` directly, or read `Page.content` or
`reader.measurer` itself, was working on empty input and has to be
rewritten against `reader.interactions`.

`createController` now throws when `reader.interactions.textSelection`
is missing. A reader from `createReader()` always provides it; only a
custom `Reader` implementation needs to add it.

### Controller members

```ts
controller.pages                 // -> reader.pageCount, reader.spreads
controller.paginationComplete    // -> delete the branch; layout is complete
controller.selectionRange        // -> controller.selectionSourceLocator
                                 //    controller.selectionSourceSpan
                                 //    controller.selectionText
controller.setLineBreaking(…)    // -> delete
```

`selectionChange` no longer carries `range`; it carries `sourceLocator`,
`sourceSpan`, `text`, `rects` and `viewportRects`.
`ResolvedAnnotationSegment.range` is removed — an annotation is addressed
by its durable source span, and a segment reports only `pageIndex` and
`rects`.

`TextRange` leaves kit's entry point but is not gone: it is still
exported by `@ritojs/core`, which is where `SearchResult.range` now
points. Code that named the type moves the import:

```ts
import type { TextRange } from '@ritojs/kit'; // -> from '@ritojs/core'
```

### Growth navigation is removed

The pending-growth navigation state, `ensureSelectionSpread`, and the
retry of a queued table-of-contents target on layout commit are gone. A
target beyond `totalSpreads` is simply out of range.

## `@ritojs/react`

Every export keeps its name. Three shapes moved:

```ts
useSelection().range; // -> .sourceLocator / .sourceSpan / .text / .rects
useRitoReader().spreads; // the navigation record above
useRitoReader().setLineBreaking; // -> delete, as on the reader and the controller
```

`useControllerEvent`'s handler was typed against the whole event map,
which let a handler read a sibling event's payload off its argument. It
now receives the payload of the event it subscribed to:

```ts
useControllerEvent(controller, 'selectionChange', (data) => data.text);
// 1.0.1 typed `data` as ReaderControllerEvents; it is now the
// selectionChange payload. A handler that reached through the map
// (data.selectionChange.text) drops the event name.
```

## What did not change

`createReader()` and its options apart from the three removed above;
`renderSpread`, `resize`, `setSpreadMode`, `setTheme`, `setTypography`,
`updateLayout`; navigation, search, annotations and footnotes through
the controller; and the pinned font policy.

Wire formats are the exception to look at twice: the reader protocol and
the publication, resource and artifact envelopes a host decodes are
unchanged in shape, but the display list inside the artifact is format 2
and is described above. A host that decodes paint output itself is not
in the "nothing to do" case.
