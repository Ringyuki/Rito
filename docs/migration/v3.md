# Migrating to 3.0

3.0 moves the last pieces of reading logic that hosts used to carry
themselves into the engine. Annotation targets are built and located by
the engine, so a highlight stored by a browser reader resolves the same
way in a native reader and the other way round; `line-height: normal` is
derived from the fonts the engine shapes with, so every host lays out
the same lines; and the chapter text a host needed to anchor annotations
itself is no longer shipped.

Most readers change two things: the stored annotation format, and the
`addAnnotation` call, which now returns a promise. The rest is smaller and
listed below: `ResolutionStatus` values are renamed, `Reader.getFootnotes()`
and `getChapterTextIndices()` are removed, the controller's unused `margin`
and `spreadGap` options are gone, and the raw reader session is no longer
exported.

## Annotations (`@ritojs/kit`, `@ritojs/react`)

### `AnnotationTarget` is the engine's format

```ts
// before (2.x)
interface AnnotationTarget {
  href: string;
  selectors: {
    sourceRange: { type: 'SourceRangeSelector'; start: SourcePoint; end: SourcePoint };
    textQuote: { type: 'TextQuoteSelector'; exact: string; prefix?: string; suffix?: string };
    textPosition: { type: 'TextPositionSelector'; start: number; end: number };
    progression: { type: 'ProgressionSelector'; chapter: number; chapterProgress: number };
  };
  text: { highlight: string; before?: string; after?: string };
}
// after (3.0)
interface AnnotationTarget {
  version: 1;
  href: string;
  sourceRange: { start: ReaderSourcePoint; end: ReaderSourcePoint };
  quote: { exact: string; prefix: string; suffix: string };
  position: { start: number; end: number; chapterLength: number };
}
```

Offsets are UTF-16 code units. `position` counts into the chapter's text
as parsed from its source, so it never depends on layout. The engine
writes and reads this JSON; a native host built on `rito_flutter` stores
and resolves the same bytes.

Targets in the 2.x shape are not read. Resolving one reports an error on
the controller's `error` event (source `'native-annotation-geometry'`)
and the record is not drawn. Convert
stored records once, with the book open, by rebuilding each target from
its old source range — 2.x source points are the same source-tree
coordinates the engine uses:

```ts
import type { Reader, ReaderAnnotationTarget, ReaderSourcePoint } from '@ritojs/core';

// The 2.x shape above, as far as the conversion reads it.
interface LegacyAnnotationTarget {
  href: string;
  selectors: { sourceRange: { start: ReaderSourcePoint; end: ReaderSourcePoint } };
  text: { highlight: string };
}

async function migrateTarget(
  reader: Reader,
  old: LegacyAnnotationTarget,
): Promise<ReaderAnnotationTarget | undefined> {
  const { start, end } = old.selectors.sourceRange;
  return reader.interactions?.createAnnotationTarget?.({
    href: old.href,
    sourceRange: { start, end },
  });
}
```

The call rejects when the engine cannot build the target — for one, when
the range no longer exists in this edition of the book — so catch it;
`undefined` only means the reader was closed or has no such interaction.
`old.text.highlight` is the text the reader highlighted, if you want to
search for it instead. The target type is `ReaderAnnotationTarget` from
`@ritojs/core`; Kit does not export it under another name, and reaches it
as `AnnotationRecord['target']`.

### `addAnnotation()` returns a promise

`ReaderController.addAnnotation()` and `useAnnotations().add` read the
selection when called and resolve once the engine has built the target.

```ts
controller.addAnnotation({ kind: 'highlight' }); // before: AnnotationRecord | undefined
await controller.addAnnotation({ kind: 'highlight' }); // after: Promise<AnnotationRecord | undefined>
```

A target the engine could not build is reported on the `error` event
with source `'annotation-target'`; the promise resolves `undefined`
rather than rejecting.

### `ResolutionStatus` names the engine's levels

| 2.x                      | 3.0             |
| ------------------------ | --------------- |
| `'exact'`                | `'exact'`       |
| `'quote-fallback'`       | `'quote'`       |
| `'position-fallback'`    | `'position'`    |
| `'progression-fallback'` | `'progression'` |
| `'orphaned'`             | `'orphaned'`    |

`'exact'` now also requires the stored range to still cover the quoted
text.

### Kit's anchoring is the engine's

Kit's own selector cascade is deleted. None of it was exported, so there
is nothing to rename: build targets with
`reader.interactions.createAnnotationTarget` and locate them with
`reader.interactions.resolveAnnotationTarget`. `ReaderSourcePoint` from
`@ritojs/core` is the type of a source point, including a reading
position's.

### The controller's `margin` and `spreadGap` options are removed

They were unused; page margins and the spread gap are reader options
(`createReader`'s `margin` and `spreadGap`).

## `@ritojs/core`

### The session API is internal

`openBrowserReaderSession()`, `createBrowserReaderSessionCanvasPresenter()`,
`RitoReaderError`, the image resource error and every `BrowserReader*`
type are no longer exported. `createReader()` is the browser's one host of
the reader session: it runs every operation on the session's artifacts
through one queue and owns each artifact until it is shown or given back,
which a host built on the raw session had to do for itself. Open books
with `createReader()`, or with `@ritojs/kit` and `@ritojs/react` on top of
it; an error it rejects with still carries the session's `code`.

### `getFootnotes()` is removed

`reader.getFootnotes()` is removed: a session answers one note by its key.
Read a note with `reader.interactions.getFootnote(key)`, with the
`footnoteKey` a page target of kind `'footnote'` carries.

### `getChapterTextIndices()` is removed

`reader.getChapterTextIndices()` and the `ChapterTextIndex` and
`ChapterTextSpan` types are removed, and a revision commit no longer
carries the book's text from the worker. Durable source ranges come from
`search()` results whose `source` is resolved, from selections, and from
`interactions.createAnnotationTarget`. To place a stored position,
`interactions.tocEntryAtPosition` names its TOC entry and
`interactions.compareSourcePositions` orders two of them.

### Line heights are the engine's own

The browser reader no longer measures `line-height: normal` with the
DOM, injects the values and reflows until they settle, and a native host
gets identical lines. Pages can break in
different places than in 2.x where the old measurement disagreed with
the fonts' metrics, so a page index stored under 2.x may point at a
neighbouring page; source-anchored positions are unaffected. A character
no registered font covers keeps the advance shaping gives it rather than
the width of the browser's system fallback glyph.

The reader diagnostics hook drops `hostLineMetrics`,
`unmetHostLineMetricRequests` and `hostLineMetricsEpochs`.
