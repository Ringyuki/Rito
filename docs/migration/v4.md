# Migrating to 4.0

4.0 draws the reader on the GPU. `@ritojs/kit` composites every frame with
WebGL2 on the canvas you give `createController`, keeps the pages it has
painted as textures in that canvas's context, and has
`reader.renderSpreadTo` paint them straight into their framebuffers: a page
of text is drawn from glyphs the browser's canvas rasterized, the same
pixels the canvas would have, and any other page is painted on a canvas and
copied in. Turns, overlays and the paper turn are drawn in the same context.

Most readers change nothing. A host that wrote its own painted page-turn
effect, or that drew on or read the display canvas through a 2D context,
changes what is listed below. Every package in the release group moves to
4.0 together.

## The display canvas has a WebGL2 context

`createController` takes the canvas's WebGL2 context. A canvas whose 2D
context was already taken cannot give it one, so do not call
`getContext('2d')` on it; `createReader` no longer does either until
`reader.renderSpread` paints into that canvas itself. Where the browser
gives no WebGL2, `createController` throws `WebGlUnavailableError`
(exported by `@ritojs/kit`).

The canvas keeps its drawing buffer, so the display can still be read back
at any time — draw it into a canvas of your own:

```ts
const copy = new OffscreenCanvas(canvas.width, canvas.height);
copy.getContext('2d')?.drawImage(canvas, 0, 0);
```

The controller keeps the book laid out at the screen's pixel ratio
(`reader.setDevicePixelRatio`, new in `@ritojs/core`) when the page zooms
or the window goes to another screen, where 3.x stretched the pages it had.
It sets the canvas's `image-rendering` itself: `pixelated` while the canvas
holds one pixel per device pixel, which the browser otherwise filtered and
showed shifted or blurred, and `auto` while a pinch magnifies it.

`paintPage` is unchanged: a host's painter still draws with a 2D context
over each page, which lands on the page under the highlights.

## Painted page-turn effects (`@ritojs/kit`)

A `PaintedTransitionEffect` draws with the display's WebGL2 context instead
of a 2D context:

| 3.x                                                 | 4.0                                                                                                                                                                             |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scene.context` (the display's 2D context)          | `scene.gl`, the display's WebGL2 context, its own framebuffer bound and cleared                                                                                                 |
| `scene.page(slot).content` and `.overlay` (bitmaps) | `scene.page(slot).texture`: the page with its overlay over it, one premultiplied texture of that context, its last row the top of the page; `.width` and `.height` are its size |
| `prepare()`                                         | `prepare(gl)`, called with the display's context when the effect is set and again after the context was lost and given back                                                     |

`scene.drawPage(slot, x, opacity?)`, `scene.width`, `scene.height`,
`scene.cssPixel`, `scene.spine` and a page's `spread`, `pixelRatio` and
`version` are as they were. Asking for a page or drawing one may paint it
first, which changes the context's program, vertex array, textures and
blending: set yours after. Layered effects (`layers(frame)`) and the
built-in `slide`, `cover`, `fade`, `none` and `createPaperTurn()` need
nothing.

## Painting a spread into WebGL (`@ritojs/core`)

`reader.renderSpreadTo(index, target)` also takes a `ReaderGlTarget`,
`{ gl, framebuffer, width, height }`: a WebGL2 context and the framebuffer
in it to paint (`null` for its canvas), sized as a 2D target would be. Both
kinds of target receive the same pixels.

## A spread's pages sit on the device grid (`@ritojs/core`)

In double mode each page is a whole number of device pixels wide, as a
browser places a frame. Where the viewport less `spreadGap` does not halve
into whole device pixels (an odd width at a ratio of 1), the pages are a
little narrower than an even split and the gap between them takes the
rest, so a book can paginate a little differently at those widths.
`getLayoutGeometry()` reports the `pageWidth` and `spreadGap` the pages were
laid out in.

`createLayoutConfig()` and the `LayoutConfigInput` type are removed: the
page geometry depends on the device pixel ratio and is the engine's to
decide. Read it from `getLayoutGeometry()`.
